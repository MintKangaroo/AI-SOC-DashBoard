## 유지되는 기능

39개 패널, 서버 권한 검사와 세션 회수, POST 로그아웃, CSRF/CSP, 감사 기록,

탐지 품질, SIEM·헌팅·MITRE·SOAR·재현·취약점 기능을 유지합니다.

추가 집계는 AI 관제 센터 하단의 **저장 증거 요약**을 펼쳐 확인합니다.
헤더 시간 범위는 이 요약·조사 큐·통합 검색·탐지 품질에 적용됩니다.
기존 파이프라인과 지도는 화면에 명시된 세션/독립 범위를 사용합니다.
LIVE는 소켓 연결 상태이며 전체 센서가 정상이라는 뜻이 아닙니다.

탐지·차단·allowlist·승인·TTL·패치 정책, 데이터베이스, 운영 환경 변수는 수정하지 않습니다.
기존 CSS를 그대로 사용하고 새 증거 컴포넌트 토큰은 같은 팔레트를 참조합니다.
백엔드 전체 revert나 데이터베이스 롤백은 필요하지 않습니다.

## `/api/console/summary` 404와 적용 순서

정적 CSS/JS/Jinja는 최신 디스크 파일인데 Python 프로세스가 옛 코드를 계속 실행하면,
새 화면이 요청하는 `/api/console/*` 라우트가 404일 수 있습니다. 이번 환경에서
포트 5055의 프로세스가 새 라우트가 추가되기 전에 시작된 상태였으며 로그인 후에도
`/api/console/summary?hours=24`의 404를 재현했습니다.

1. 변경 후 테스트를 실행하고 배포할 커밋과 실행 프로세스의 작업 디렉터리를 확인합니다.
2. 실제 SOAR 실행·패치 작업이 진행 중인지 확인합니다. 작업 중에는 종료하지 않습니다.
3. 해당 서비스의 실행 방식으로 서버를 갱신합니다. 환경 변수·`.env`·데이터 디렉터리·응답 정책을 유지합니다.
   수동 실행 환경은 PID 파일과 `/proc/<pid>/cmdline`, 작업 디렉터리를 대조한 정확한 프로세스만 종료합니다.
   다른 서비스에 영향을 주는 `pkill -f python` 같은 패턴 종료는 사용하지 않습니다.
4. 서버와 syslog 리스너가 정상 기동했는지 확인하고 다시 로그인합니다.
   기존 단일 관리자 모드의 메모리 세션은 재시작 후 다시 인증해야 합니다.
5. 인증된 요청으로 `/api/console/summary?hours=24`의 **200 JSON**, Socket.IO 연결,
   SOAR 승인·차단 모드·TTL·allowlist와 센서 상태를 확인합니다.
6. 브라우저를 새로고침합니다. 응답 캐시가 남아 있으면 강력 새로고침을 사용합니다.

관리되는 다중 사용자 데이터베이스의 사용 여부는 기존 `AUTH_USERS_DB` 설정에 따릅니다.
화면 복원을 이유로 인증이나 역할 제한을 해제하지 않습니다.
